Red Hat Connectivity Link · Lab isolado

Interceptação de requisições no Gateway

Gateway dedicado req030-interceptor-gateway com dois listeners HTTP em hostnames separados — cada estratégia validada de forma independente.

req030-extauthz.* · ext_authz req030-mirror.* · RequestMirror req030-gateway + req030-apps

● Introdução

Este lab demonstra duas formas de entregar a requisição completa do cliente a um componente interno do cluster. O foco são os mecanismos do Envoy/Istio, não a aplicação de exemplo em si.

Princípio: qualquer serviço HTTP interno pode ocupar o papel de interceptor — basta apontar o extension provider (envoyExtAuthzHttp) e/ou o filtro RequestMirror para o seu Deployment/Service.
ListenerHostnameEstratégia
http-extauthz req030-extauthz.${RHCL_ZONE_ROOT_DOMAIN} Autorização externa bloqueante (ext_authz)
http-mirror req030-mirror.${RHCL_ZONE_ROOT_DOMAIN} Espelhamento assíncrono (RequestMirror)

◎ Arquitetura

Tráfego entra por OpenShift Route (TLS edge), passa pelo gateway dedicado e segue um dos dois caminhos conforme o hostname.

flowchart TB CLIENT["Cliente"] ROUTE["OpenShift Route\n(edge TLS)"] GW["req030-interceptor-gateway\nGatewayClass: istio"] CLIENT --> ROUTE --> GW GW -->|"http-extauthz · síncrono"| AUTHZ["AuthorizationPolicy CUSTOM\next_authz"] GW -->|"http-mirror · assíncrono"| MIRROR["HTTPRoute\nRequestMirror filter"] AUTHZ -->|"bloqueia até resposta"| INT["request-interceptor\nreq030-apps"] MIRROR -.->|"cópia paralela"| INT AUTHZ --> HW["hello-world\nreq030-apps"] MIRROR --> HW HW --> CLIENT
Gateway dedicado — hostnames separados isolam cada estratégia (síncrona vs assíncrona).
Design do lab: em produção você pode combinar as duas estratégias em uma única rota; aqui usamos hostnames distintos para validação clara (mesmo padrão do req050 com listeners CRL/OCSP separados).

Em modo PoC o interceptor sempre permite (200 OK) e registra headers/body nos logs.

1 External authorization — http-extauthz

O Envoy deve chamar o interceptor e receber allow/deny antes de encaminhar ao hello-world. Use quando a interceptação pode bloquear tráfego.

⏱
Bloqueia o fluxo

ext_authz síncrono

req030-extauthz.<zone>
  • Istio CR: envoyExtAuthzHttp
  • AuthorizationPolicy com action: CUSTOM
  • Path no interceptor: /check/...
  • Body até 8192 bytes

Fluxo

  1. Cliente chama https://req030-extauthz.<zone>/
  2. Envoy aplica AuthorizationPolicy para o host
  3. Envoy POST em request-interceptor:8080/check/...
  4. Interceptor retorna 200 + headers de inspeção
  5. Envoy encaminha para hello-world:8080
sequenceDiagram participant C as Cliente participant E as Envoy Gateway participant I as request-interceptor participant B as hello-world C->>E: POST / + headers + body E->>I: POST /check/ — ext_authz I-->>E: 200 OK + X-Inspected-By E->>B: POST / B-->>E: 200 resposta E-->>C: 200 resposta

Extension provider (trecho)

- name: req030-request-interceptor
  envoyExtAuthzHttp:
    service: request-interceptor.req030-apps.svc.cluster.local
    port: 8080
    pathPrefix: /check
    includeRequestBodyInCheck:
      maxRequestBytes: 8192

Aplicado por deploy-istio-extension-provider.sh (merge-patch no Istio CR existente).

2 RequestMirror — http-mirror

O Envoy envia uma cópia fire-and-forget ao interceptor enquanto a requisição original segue para hello-world. Use para observabilidade assíncrona.

↗
Não bloqueia

RequestMirror assíncrono

req030-mirror.<zone>
  • Filtro RequestMirror no HTTPRoute
  • Path original preservado
  • Falha do mirror não afeta o cliente
  • Sem impacto de latência no caminho crítico

Fluxo

  1. Cliente chama https://req030-mirror.<zone>/
  2. Envoy aplica filtro RequestMirror
  3. Cópia assíncrona vai para request-interceptor
  4. Original segue para hello-world sem esperar o mirror
sequenceDiagram participant C as Cliente participant E as Envoy Gateway participant I as request-interceptor participant B as hello-world C->>E: POST / + headers + body par Caminho principal E->>B: POST / B-->>E: 200 resposta E-->>C: 200 resposta and Espelhamento E->>I: POST / — cópia idêntica Note over I: resposta descartada end
Atenção: RequestMirror é espelhamento, não split de tráfego ou canary.

⇄ Comparação

Aspecto ext_authz RequestMirror
Bloqueia requisição?Sim (se interceptor nega)Não
Impacto de latênciaRound-trip síncronoMínimo (async)
Superfície de configIstio CR + AuthorizationPolicyFiltro no HTTPRoute

▶ Deploy

Pré-requisitos: OpenShift com Service Mesh 3.x (Istio/Sail), Gateway API, GatewayClass: istio, e acesso ao Docker Hub para a imagem do interceptor.

Deploy completo

export RHCL_ZONE_ROOT_DOMAIN=mycluster.sandbox546.opentlc.com   # ajuste ao seu cluster
cd tests/req030/manifests
./deploy.sh

O script executa 8 etapas: namespaces, apps, gateway, extension provider (interativo), AuthorizationPolicy, HTTPRoutes e OpenShift Routes.

Extension provider: na etapa 6 o script lista os Istio CRs do cluster e pede qual patchar — nunca substitua a lista inteira de extensionProviders.

✓ Validar

Teste automatizado

export RHCL_ZONE_ROOT_DOMAIN=mycluster.sandbox546.opentlc.com
cd tests/req030/manifests
./test-req030.sh

Payload de validação (ext_authz)

curl -sk -X POST "https://req030-extauthz.${RHCL_ZONE_ROOT_DOMAIN}/" \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer demo-token' \
  -H 'X-Request-ID: req030-demo-001' \
  -d '{"hello":"world","item":30}'

curl -sk "https://req030-mirror.${RHCL_ZONE_ROOT_DOMAIN}/"
oc -n req030-apps logs deployment/request-interceptor --tail=30

Esperado: HTTP 200 do hello-world; logs do interceptor com método, URI, headers, body e X-Request-ID.

Evidências no cluster

oc -n req030-apps get deploy hello-world request-interceptor
oc -n req030-gateway get gateway req030-interceptor-gateway
oc -n req030-gateway get httproute
oc get istio -A -o jsonpath='{range .items[*]}{.metadata.namespace}/{.metadata.name}{": "}{.spec.values.meshConfig.extensionProviders[*].name}{"\n"}{end}'
oc -n req030-apps logs deployment/request-interceptor --tail=20 | grep -E 'REQUEST|X-Request-ID'

Critérios de sucesso

  • hello-world e request-interceptor Available em req030-apps
  • Gateway Programmed com listeners http-extauthz e http-mirror
  • https://req030-extauthz.<zone>/ retorna HTTP 200
  • https://req030-mirror.<zone>/ retorna HTTP 200
  • Logs do interceptor mostram tráfego de ambos os hostnames
  • Istio CR inclui req030-request-interceptor em extensionProviders
