# Expor APIs com HTTP/1.1, HTTP/2 e HTTP/3

## Requisito Demonstrado

- **Item 57: Expor APIs usando HTTP versões 1.1, 2 e 3**

---

## Visão Geral

O objetivo deste item é demonstrar que o Kuadrant/Istio é capaz de expor a mesma API através das três versões do protocolo HTTP, negociando a versão adequada com cada cliente:

| Versão | Transporte | Negociação |
|--------|-----------|------------|
| HTTP/1.1 | TCP (porta 80 ou 443) | Padrão para HTTP; TLS sem ALPN |
| HTTP/2 | TCP TLS (porta 443) | ALPN `h2` negociado no handshake TLS |
| HTTP/3 | UDP/QUIC (porta 443) | Anunciado via header `alt-svc: h3=":443"` |

O gateway `rhcl-apps-gateway` (em `openshift-ingress`) expõe dois listeners dedicados ao req057:
- `req057-http` (porta 80): HTTP/1.1 cleartext
- `req057-https` (porta 443): HTTP/1.1 e HTTP/2 via ALPN TLS; HTTP/3 anunciado via `alt-svc`

> **Nota de arquitetura:** Este item reutiliza o gateway existente `rhcl-apps-gateway` em `openshift-ingress`. Isso elimina a necessidade de criar um gateway separado e aproveita o DNS wildcard gerenciado automaticamente pelo OpenShift nesse namespace.

---

## Pré-requisitos

1. **Login como cluster-admin:**
   ```bash
   oc login --token=<admin-token> --server=<cluster-api>
   ```

2. **Variáveis de ambiente:**
   ```bash
   export NS=req057
   export CLUSTER_DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
   export HOST=banking-api.${CLUSTER_DOMAIN}
   ```

3. **`curl` com suporte a HTTP/3** (para a validação do item 3):
   ```bash
   curl --version | grep -i http3
   # deve aparecer: Features: [...] HTTP3 [...]
   ```
   Se o `curl` do cliente não tiver suporte a HTTP/3, use a seção [Validação alternativa HTTP/3](#validação-alternativa-http3).

## Deploy

### 1. Criar namespace

```bash
oc apply -f req057/namespace.yaml
```

### 2. Atualizar o hostname nos manifests

Substitua `<CLUSTER_DOMAIN>` pelo domínio real do cluster:

```bash
CLUSTER_DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
sed -i "s/banking-api.apps.cluster-qrqbr.qrqbr.sandbox1142.opentlc.com/banking-api.${CLUSTER_DOMAIN}/g" \
  req057/httproute.yaml
```

### 3. Adicionar listeners ao gateway compartilhado

Os listeners `req057-http` (porta 80) e `req057-https` (porta 443) precisam ser adicionados ao `rhcl-apps-gateway`:

```bash
# Adicionar listener HTTP/80
oc patch gateway rhcl-apps-gateway -n openshift-ingress --type='json' -p='[
  {"op":"add","path":"/spec/listeners/-","value":{
    "name":"req057-http",
    "hostname":"banking-api.'"${CLUSTER_DOMAIN}"'",
    "port":80,
    "protocol":"HTTP",
    "allowedRoutes":{"namespaces":{"from":"All"}}
  }}
]'

# Adicionar listener HTTPS/443 usando o certificado wildcard existente
oc patch gateway rhcl-apps-gateway -n openshift-ingress --type='json' -p='[
  {"op":"add","path":"/spec/listeners/-","value":{
    "name":"req057-https",
    "hostname":"banking-api.'"${CLUSTER_DOMAIN}"'",
    "port":443,
    "protocol":"HTTPS",
    "allowedRoutes":{"namespaces":{"from":"All"}},
    "tls":{
      "mode":"Terminate",
      "certificateRefs":[{
        "group":"",
        "kind":"Secret",
        "name":"cert-manager-ingress-cert",
        "namespace":"openshift-ingress"
      }]
    }
  }}
]'
```

### 4. Configurar health check do ELB para TCP pass-through

O listener HTTPS usa TLS termination no Envoy (não no ELB). O ELB precisa estar em modo TCP passthrough. Aplique as anotações no Service do gateway:

```bash
GW_SVC=$(oc get svc -n openshift-ingress -l gateway.networking.k8s.io/gateway-name=rhcl-apps-gateway -o name | head -1 | cut -d/ -f2)

oc annotate svc $GW_SVC -n openshift-ingress \
  "service.beta.kubernetes.io/aws-load-balancer-backend-protocol=tcp" \
  "service.beta.kubernetes.io/aws-load-balancer-healthcheck-protocol=HTTP" \
  "service.beta.kubernetes.io/aws-load-balancer-healthcheck-path=/healthz/ready" \
  "service.beta.kubernetes.io/aws-load-balancer-healthcheck-port=$(
    oc get svc $GW_SVC -n openshift-ingress -o jsonpath='{.spec.ports[?(@.name=="status-port")].nodePort}'
  )" \
  --overwrite
```

> **Por que isso é necessário:** A Classic ELB da AWS, ao detectar a porta 443 com nome `*-https` no Service, pode criar um listener HTTPS que termina TLS no próprio ELB. Como o Envoy já gerencia o TLS, o ELB deve operar em modo TCP passthrough. O health check na porta de status (15021) via HTTP garante que o backend seja marcado como saudável corretamente.

### 5. Aplicar os recursos do req057

```bash
# TLSPolicy (no mesmo namespace do gateway)
oc apply -f req057/tlspolicy.yaml

# HTTPRoute e ReferenceGrant
oc apply -f req057/httproute.yaml
oc apply -f req057/referencegrant.yaml
```

### 6. Configurar autenticação por API key

O secret da API key **deve estar no namespace `kuadrant-system`**, pois é onde o Authorino busca os secrets (quando `allNamespaces: false` está configurado no AuthConfig).

```bash
# Editar o valor da chave antes de aplicar
sed -i "s/redhat/minha-chave-secreta/g" req057/secret-apikey.yaml

oc apply -f req057/secret-apikey.yaml
oc apply -f req057/authpolicy-apikey.yaml
```

Verificar que o Authorino reconheceu o Secret:

```bash
oc -n kuadrant-system get secret banking-api-apikey -o jsonpath='{.metadata.labels}'
# deve conter: authorino.kuadrant.io/managed-by=authorino

oc -n req057 get authpolicy banking-api-route-apikey -o jsonpath='{.status.conditions}'
```

### 7. Aguardar o DNSRecord ser publicado

O OpenShift cria automaticamente um DNSRecord para cada hostname nos listeners do gateway em `openshift-ingress`:

```bash
oc get dnsrecord -n openshift-ingress -w
# Aguardar: status Published=True para banking-api.<CLUSTER_DOMAIN>
```

## Validação

### HTTP/1.1

Listener HTTP (porta 80), sem TLS:

```bash
curl -si --http1.1 http://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta"
```

**Resultado esperado:**

```
HTTP/1.1 200 OK
```

---

### HTTP/2

Listener HTTPS (porta 443); Istio/Envoy negocia `h2` via ALPN no handshake TLS:

```bash
curl -si -k https://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta"
```

**Resultado esperado:**

```
HTTP/2 200
```

Para confirmar que o ALPN foi negociado:

```bash
curl -v -k https://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta" 2>&1 | grep -E "ALPN|HTTP/"
# ALPN: server accepted h2
# < HTTP/2 200
```

---

### HTTP/3

O header `alt-svc` retornado nas respostas HTTPS anuncia a disponibilidade de HTTP/3. Clientes compatíveis fazem upgrade automaticamente na próxima requisição.

**Verificar o header `alt-svc` na resposta:**

```bash
curl -si -k https://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta" | grep alt-svc
# alt-svc: h3=":443"; ma=86400
```

**Requisição direta via HTTP/3 (requer curl com suporte a HTTP/3):**

```bash
curl -v --http3-only -k https://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta"
```

**Resultado esperado:**

```
* QUIC ver quic
< HTTP/3 200
< alt-svc: h3=":443"; ma=86400
```

---

### Validação alternativa HTTP/3

Se o `curl` do cliente não tiver suporte a HTTP/3, use um pod temporário no cluster:

```bash
oc run curl-h3 -n $NS --image=curlimages/curl:latest --restart=Never -it --rm \
  -- curl -v --http3-only -k https://$HOST/api/v1/accounts/summary -H "api-key: minha-chave-secreta"
```

---

### Resumo das versões negociadas

| Comando | Listener | Versão negociada |
|---------|----------|-----------------|
| `curl --http1.1 http://...` | HTTP / porta 80 | HTTP/1.1 |
| `curl --http1.1 -k https://...` | HTTPS / porta 443 | HTTP/1.1 (TLS sem h2) |
| `curl -k https://...` | HTTPS / porta 443 | HTTP/2 (ALPN h2) |
| `curl --http3-only -k https://...` | HTTPS/QUIC / UDP 443 | HTTP/3 |

---

## Notas técnicas

- **HTTP/1.1 vs HTTP/2 no mesmo listener HTTPS:** O Istio/Envoy negocia a versão via ALPN. Se o cliente oferece `h2`, o servidor aceita e usa HTTP/2. Se não, cai para HTTP/1.1. Não é necessário listener separado.
- **Certificado TLS:** O listener `req057-https` usa o Secret `cert-manager-ingress-cert` em `openshift-ingress`, que é um certificado wildcard `*.apps.<CLUSTER_DOMAIN>` gerenciado pelo cert-manager com Let's Encrypt.
- **AWS Classic ELB em TCP mode:** A porta 443 deve usar TCP passthrough (não HTTPS no ELB), pois o Envoy gerencia a terminação TLS. As anotações `aws-load-balancer-backend-protocol=tcp` e o health check correto são essenciais.
- **Secrets do Authorino:** O Secret da API key deve estar no namespace `kuadrant-system`, pois o Authorino em configuração `allNamespaces: false` só monitora secrets nesse namespace.
- **HTTP/3 é experimental no OSSM 2.x:** O suporte a QUIC requer Istio 1.20+ e pode não estar habilitado por padrão. Confirme a versão do Istio com `oc -n istio-system get deploy istiod -o jsonpath='{.spec.template.spec.containers[0].image}'`.
- **Firewall/OpenShift:** HTTP/3 requer UDP 443 aberto no Security Group AWS e no NodePort. Em ambientes cloud, verifique se UDP 443 está permitido no ELB e nas regras de rede dos nós.

---

### Validação da autenticação

Sem a key → deve retornar `401`:

```bash
curl -si -k https://$HOST/api/v1/accounts/summary | head -1
# HTTP/2 401
```

Com a key correta → deve retornar `200`:

```bash
curl -si -k https://$HOST/api/v1/accounts/summary \
  -H "api-key: minha-chave-secreta" | head -1
# HTTP/2 200
```

## Limpeza

```bash
oc delete -f req057/authpolicy-apikey.yaml --ignore-not-found
oc delete -f req057/secret-apikey.yaml --ignore-not-found
oc delete -f req057/httproute.yaml --ignore-not-found
oc delete -f req057/tlspolicy.yaml --ignore-not-found
oc delete -f req057/namespace.yaml --ignore-not-found

# Remover listeners adicionados ao gateway compartilhado
CLUSTER_DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
oc patch gateway rhcl-apps-gateway -n openshift-ingress --type='json' -p='[
  {"op":"remove","path":"/spec/listeners/3"},
  {"op":"remove","path":"/spec/listeners/2"}
]'

# Remover anotações do ELB (se aplicável)
GW_SVC=$(oc get svc -n openshift-ingress -l gateway.networking.k8s.io/gateway-name=rhcl-apps-gateway -o name | head -1 | cut -d/ -f2)
oc annotate svc $GW_SVC -n openshift-ingress \
  service.beta.kubernetes.io/aws-load-balancer-backend-protocol- \
  service.beta.kubernetes.io/aws-load-balancer-healthcheck-protocol- \
  service.beta.kubernetes.io/aws-load-balancer-healthcheck-path- \
  service.beta.kubernetes.io/aws-load-balancer-healthcheck-port- \
  --overwrite
```
