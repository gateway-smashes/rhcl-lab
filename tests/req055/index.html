Expose APIs with TLS 1.2 / 1.3 page: …

Demonstrate that the API exposed by the RHCL / Gateway accepts both TLS 1.2 and TLS 1.3 handshakes, and that legacy versions (TLS 1.0 / 1.1 / SSLv3) are rejected.

Scenario

[ client ]                                  [ RHCL / Gateway ]              [ Pod ]
    |                                              |                          |
    |  ClientHello (TLS 1.3 preferred)             |                          |
    |--------------------------------------------> |  terminates TLS          |
    |     ServerHello: TLSv1.3 + AES_GCM           |  -------- h2c ---------> |
    |                                              |                          |
    |  ClientHello (forced TLS 1.2)                |                          |
    |--------------------------------------------> |  ServerHello: TLSv1.2    |
    |                                              |                          |
    |  ClientHello (forced TLS 1.0/1.1)            |                          |
    |--------------------------------------------> |  ALERT: protocol_version |
Browser limitation. Browsers (and the fetch() API) do not let JavaScript pick a TLS version — that's negotiated by the OS/network stack. This page can therefore only show that some handshake worked from the browser. To prove TLS 1.2 and 1.3 independently, copy the curl / openssl s_client commands at the bottom and run them from a shell against the same backend URL.
