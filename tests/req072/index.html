REQ 72

IP-based ACL

Source-IP blocking (deny-list) at the gateway, with a single validated engine: an OPA/Rego AuthPolicy evaluated by Authorino over x-forwarded-for. Two variants — block a single IP, or block a CIDR range. Target: the ipfilter-php probe (route ipfilter, endpoint /api/ip). Apply one manifest and watch 200 vs 403.

Other approaches exist (OPA allow-list, CEL AuthPolicy, native Envoy RBAC via EnvoyFilter) but are intentionally not shown here — this package keeps only the OPA deny-list path validated end to end. See tests/req072.md for the full write-up.

How it works

The AuthPolicy carries one inline-Rego authorization rule that Authorino runs on every request. allow is set to true only for non-blocked traffic; when the request matches the block list, allow stays undefined, which Authorino treats as a deny (403). No default allow is needed.

Variant 1 — block a single IP (manifest 01)
xff := object.get(input.context.request.http.headers, "x-forwarded-for", "")

allow {
  not contains(xff, "203.0.113.10")
}
Variant 2 — block a CIDR range (manifest 02)
blocked_ranges := [
  "203.0.113.0/24",
]

xff := object.get(input.context.request.http.headers, "x-forwarded-for", "")

xff_ips := [trim(ip, " ") | ip := split(xff, ",")[_]]

blocked {
  ip := xff_ips[_]
  count(net.cidr_contains_matches(blocked_ranges, [ip])) > 0
}

allow {
  not blocked
}

Console

The forge-and-fetch buttons below call /api/ip with a spoofed x-forwarded-for. They work when this page is served same-origin with the probe (i.e. at https://ipfilter.<domain>/, which the ipfilter-php app already serves). From another origin the browser blocks the cross-origin fetch (these deny-list manifests carry no CORS headers) — use the app's own page or curl below.

Defaults: blocked → 203.0.113.10 (matched by both variants); allowed → 8.8.8.8. For the range variant, the whole 203.0.113.0/24 is blocked.

Apply

Run from the repository root. The playbook creates a default AuthPolicy named ipfilter-ip-acl on the same route; only one AuthPolicy is Enforced per target, so remove it first to avoid a two-policies-one-target conflict.

File Engine Mode CR / namespace
00-httproute-ipfilter.yaml — — HTTPRoute / rhcl-apps
01-block-ip-opa.yaml OPA/Rego → Authorino Deny-list (single IP) AuthPolicy / rhcl-apps
02-block-range-opa.yaml OPA/Rego → Authorino Deny-list (CIDR range) AuthPolicy / rhcl-apps 
export ROOT=tests/req072/manifests
export RHCL_ZONE_ROOT_DOMAIN=azuredns.rhcl.com.br  # adjust

# Route + ipfilter-php service (skip if apps-install already created it)
envsubst < $ROOT/00-httproute-ipfilter.yaml | oc apply -f -

# Remove the playbook default policy to avoid a target conflict
oc -n rhcl-apps delete authpolicy ipfilter-ip-acl --ignore-not-found

# Block a single IP...
oc apply -f $ROOT/01-block-ip-opa.yaml
# ...or block a CIDR range (same name — replaces the one above):
# oc apply -f $ROOT/02-block-range-opa.yaml

oc -n rhcl-apps wait authpolicy/ipfilter-block-xff \
  --for=condition=Enforced=True --timeout=120s
