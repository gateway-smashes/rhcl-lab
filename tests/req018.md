# Item 18 — Monitoração de Custo

> **Objetivo demo:** mostrar, por consumidor de API, quantas chamadas
> fez, quantos tokens de IA gastou, **e quanto isso custou em BRL**,
> num período configurável — tudo em cima do RHCL + observabilidade
> nativa do OpenShift, sem sistema de billing externo.

## Requisito

| Item   | Requisito                                                                    |
| ------ | ---------------------------------------------------------------------------- |
| **18** | Monitoração de custo das APIs por consumidor: chamadas HTTP + tokens AI, com preço por tier. |

---

## TL;DR — O que essa stack entrega

Uma **página "Cost"** no plugin `Custom Connectivity Link` e um **dashboard
Grafana `RHCL API Costs`** que exibem, por consumidor:

- **Calls (24h)** — chamadas HTTP contabilizadas no gateway (Istio)
- **Tokens (24h)** — soma prompt+completion emitida pelo backend
- **Cost (24h)** — `Calls × preço_por_chamada + Tokens × preço_por_token`
- **Δ vs 24h anteriores** — comparativo dia-a-dia

A **tabela de preços é per-tier** (`gold` / `silver` / `bronze` / `anonymous`),
mora numa ConfigMap, e é reconfigurável em runtime sem rebuild.

---

## Por que essa abordagem (e não outra)

Poderia-se contabilizar bytes no Envoy, integrar com um billing SaaS, ou
gerar CDRs por request. Escolhemos **métricas Prometheus agregadas** por 3
razões:

1. **Zero infra nova.** O RHCL PoC já traz Istio + UWM + Grafana Operator.
   Reaproveitamos `istio_requests_total` e adicionamos UM contador
   Micrometer no backend.
2. **Cardinalidade controlada.** Labels são `consumer_id + route`, sem
   trace ID. Retenção do UWM segura sem custo extra de storage.
3. **Preço mutável em runtime.** ConfigMap watchada pelo plugin → operador
   ajusta o preço do `gold` e a UI reflete em <60s.

Trade-off: **não é billing** — é monitoração. Não emite fatura, não
concilia contra ERP. Serve pra dashboard de FinOps interno / alerting
por consumidor caro.

## Os 4 pilares (o que criamos e por quê)

### Pilar 1 — Contador de tokens no backend

**Arquivo:** [`apps/backend/banking-api/src/main/java/io/gatewaysmashes/rhcl/ai/AiTokenMetrics.java`](../apps/backend/banking-api/src/main/java/io/gatewaysmashes/rhcl/ai/AiTokenMetrics.java)

Métrica emitida:

```
bank_ai_tokens_total{kind, consumer_id, model, route}
```

- `kind` = `prompt` ou `completion` (2 séries por chamada — permite
  preço assimétrico "token in" vs "token out" no futuro)
- `consumer_id` = valor do header `x-consumer-id` que o gateway injeta
  após autenticação; `"anonymous"` quando não passou por Authorino
- `model` = o modelo LLM pedido (`banking-llm`, etc.)
- `route` = **template** do path (`/api/v1/chat/completions`), nunca o
  path parametrizado — evita explosão de séries por IDs na URL

Chamadores: [`AiV1CompletionsResource.java`](../apps/backend/banking-api/src/main/java/io/gatewaysmashes/rhcl/api/AiV1CompletionsResource.java),
[`AiV1ExtraResource.java`](../apps/backend/banking-api/src/main/java/io/gatewaysmashes/rhcl/api/AiV1ExtraResource.java) —
incrementam ao terminar cada chamada de IA (chat/completions,
embeddings, responses).

Exposição: `/q/metrics` — endpoint padrão do Quarkus Micrometer.

### Pilar 2 — Telemetry CR pra rotular o consumidor nas métricas do gateway

**Arquivo template:** [`automation/roles/grafana/templates/telemetry-istio.yml.j2`](../automation/roles/grafana/templates/telemetry-istio.yml.j2)
**Manifest renderizado:** [`manifests/03-telemetry-consumer-labels.yaml`](req018/manifests/03-telemetry-consumer-labels.yaml)

Sem essa Telemetry CR, `istio_requests_total` não tem o label
`request_headers_x_consumer_id` — a tabela de custos ficaria colapsada
num único bucket "sem consumer".

**Gotcha crítica** (documentada no arquivo):

> Uma Telemetry CR com `selector: {}` (default) só se aplica a workloads
> com sidecar injetado. Gateways da Gateway API do OpenShift são **Envoy
> standalone** (sem webhook de injeção), então o istiod ignora
> silenciosamente e o `istio.stats` Wasm filter nunca recebe os
> tagOverrides — o `istio_requests_total` sai sem os 3 labels custom e
> os dashboards ficam vazios. **Solução:** setar
> `spec.targetRefs` apontando pro Gateway explicitamente.

Labels que a CR adiciona:

| Label                            | Fonte                               |
| -------------------------------- | ----------------------------------- |
| `request_url_path`               | `request.url_path`                  |
| `request_headers_x_consumer_id`  | `request.headers['x-consumer-id']`  |
| `route_name`                     | `xds.route_name` (nome do HTTPRoute)|

### Pilar 3 — ServiceMonitor pro UWM raspar `/q/metrics`

**Arquivo template:** [`automation/roles/apps/templates/banking-api-servicemonitor.yml.j2`](../automation/roles/apps/templates/banking-api-servicemonitor.yml.j2)
**Manifest renderizado:** [`manifests/02-servicemonitor-banking-api.yaml`](req018/manifests/02-servicemonitor-banking-api.yaml)

Sem esse ServiceMonitor, o `bank_ai_tokens_total` fica preso dentro do
pod — o Prometheus do UWM (User Workload Monitoring) não tem discovery
no namespace `rhcl-apps` por padrão.

**Pré-requisito no cluster:** UWM habilitado. Isso é feito editando o
`cluster-monitoring-config` ConfigMap no `openshift-monitoring`:

```yaml
data:
  config.yaml: |
    enableUserWorkload: true
```

O role Ansible NÃO patcha isso automaticamente porque é config
cluster-wide, comum de já estar setada em ambientes de cliente.

### Pilar 4 — Tabela de preços em ConfigMap

**Fonte da verdade:** variável Ansible `apps_cost_pricing` em
[`automation/inventories/example/group_vars/all.yml`](../automation/inventories/example/group_vars/all.yml)

**Renderização:** [`automation/roles/custom_console/templates/config-configmap.yml.j2`](../automation/roles/custom_console/templates/config-configmap.yml.j2)
serializa como JSON no campo `costPricing` da ConfigMap
`custom-rhcl-console-config` no namespace `custom-rhcl-console`.

**Manifest exemplo:** [`manifests/04-plugin-config-pricing.yaml`](req018/manifests/04-plugin-config-pricing.yaml)

**Consumidores:**
- **Plugin:** `console-plugin/src/hooks/useCostByConsumer.ts` watcha a
  ConfigMap via `useK8sWatchResource` — mudanças propagam sem restart do plugin.
- **Grafana:** o dashboard tem 2 variáveis manuais (`price_calls_per_1k`,
  `price_tokens_per_1k`) que o operador edita no topo do dashboard.
  Grafana não lê ConfigMap direto (evita RBAC no Grafana pra API do
  cluster).

## Como montar a tabela de custos

A ConfigMap `custom-rhcl-console-config` tem dois campos que controlam
o cálculo:

```yaml
data:
  costCurrency: "BRL"          # string livre — só rótulo, não converte
  costPricing: |
    {
      "gold":      { "tokens_per_1k": 0.10, "calls_per_1k": 0.05 },
      "silver":    { "tokens_per_1k": 0.20, "calls_per_1k": 0.10 },
      "bronze":    { "tokens_per_1k": 0.40, "calls_per_1k": 0.20 },
      "anonymous": { "tokens_per_1k": 0.50, "calls_per_1k": 0.25 }
    }
```

**Chaves (tiers):** devem bater com o `spec.plan` da APIProduct/APIKey.
O plugin descobre o tier de cada APIKey lendo a anotação
`secret.kuadrant.io/plan-id` no Secret da chave. `anonymous` é o fallback
pra requests sem consumer_id (endpoints com `anonymous: {}` no
AuthPolicy — nossos endpoints de IA no PoC).

**Valores:**
- `calls_per_1k` — custo em `costCurrency` por 1.000 chamadas HTTP
- `tokens_per_1k` — custo em `costCurrency` por 1.000 tokens IA (prompt + completion)

**Fórmula (aplicada pelo plugin):**

```
cost_por_consumidor = calls × pricing[tier].calls_per_1k / 1000
                    + tokens × pricing[tier].tokens_per_1k / 1000
```

**Onde configurar (3 caminhos, todos válidos):**

### Caminho A — via Ansible (canônico, sobrevive a reinstalação)

Editar [`automation/inventories/example/group_vars/all.yml`](../automation/inventories/example/group_vars/all.yml)
(ou passar via env `APPS_COST_PRICING` como YAML/JSON), rodar
`ansible-playbook playbooks/apps-install.yml`.

### Caminho B — via ConfigMap direto (mais rápido, ideal pra demo)

```bash
oc -n custom-rhcl-console edit configmap custom-rhcl-console-config
# Editar os campos costCurrency e costPricing e salvar.
# O plugin re-renderiza sozinho em <60s (useK8sWatchResource).
```

### Caminho C — via portal do desenvolvedor (UI)

Na página **Administration → System Settings** do developer portal, os
campos `Currency` e `Pricing (JSON)` mostram/editam a MESMA ConfigMap
(o portal-backend usa `oc patch` internamente via API).

## Passo a passo — reproduzir do zero

Pré-requisitos assumidos:
- OpenShift 4.20+ com RHCL 1.3.4 instalado (Gateway API, Kuadrant, OSSM 3)
- UWM habilitado (`enableUserWorkload: true` no `cluster-monitoring-config`)
- Grafana Operator + GrafanaInstance labelada `dashboards: rhcl` em `rhcl-grafana`
- Plugin `custom-rhcl-console` já instalado no cluster
- banking-api rodando em `rhcl-apps` com imagem que emite `bank_ai_tokens_total`
  (imagem `quay.io/hodrigohamalho/banking-api:latest` já traz)

```bash
cd tests/req018/manifests

# ─── 1. Coletar métricas HTTP com label de consumer ───────────────────────
# Telemetry CR — sem isso, istio_requests_total sai sem consumer_id.
oc apply -f 03-telemetry-consumer-labels.yaml

# ─── 2. Fazer o UWM raspar /q/metrics do banking-api ──────────────────────
# ServiceMonitor — sem isso, bank_ai_tokens_total nunca chega no Prometheus.
oc apply -f 02-servicemonitor-banking-api.yaml

# Verificar que o UWM enxergou os targets em ~30s:
oc -n openshift-user-workload-monitoring get pods
oc -n rhcl-apps get servicemonitor banking-api

# ─── 3. Publicar a tabela de preços ───────────────────────────────────────
# ConfigMap consumida por plugin (watch) e portal (patch API).
# EDITE os valores antes de aplicar — os defaults abaixo são de demo.
oc apply -f 04-plugin-config-pricing.yaml

# ─── 4. Dashboard Grafana ─────────────────────────────────────────────────
# ConfigMap com o JSON de 14 KB (mantido fora do CR pra facilitar update).
oc -n rhcl-grafana create configmap rhcl-api-costs-json \
  --from-file=dashboard.json=./dashboard-api-costs.json

# GrafanaDashboard CR que aponta pra ConfigMap acima.
oc apply -f 01-dashboard-api-costs.yaml

# ─── 5. Gerar tráfego pra ter dado no dashboard ───────────────────────────
../../simulate-api-traffic.sh --target=banking --forever --rps=8
# (Ctrl-C quando tiver dado suficiente. 2-3 min já popula bem.)
```

Ou tudo de uma vez:

```bash
./scripts/apply.sh
```

## Validação

Script pronto: `./scripts/validate.sh` — roda todos os checks abaixo.

### 1. banking-api está emitindo o counter?

```bash
POD=$(oc -n rhcl-apps get pods -l app=banking-api-v1 -o jsonpath='{.items[0].metadata.name}')
oc -n rhcl-apps port-forward $POD 18080:8080 >/dev/null 2>&1 &
sleep 3
curl -s http://localhost:18080/q/metrics | grep '^bank_ai_tokens_total' | head
kill %1
```

Esperado: pelo menos 1 série por chamada de `/api/v1/chat/completions`,
`/api/v1/embeddings`, `/api/v1/responses`, com `consumer_id="..."` (ou
`"anonymous"` se o endpoint for público).

### 2. Prometheus / Thanos vê o counter?

```bash
THANOS=$(oc -n openshift-monitoring get route thanos-querier -o jsonpath='{.spec.host}')
curl -sk -H "Authorization: Bearer $(oc whoami -t)" \
  "https://$THANOS/api/v1/query?query=bank_ai_tokens_total" \
  | jq '.data.result | length'
```

Esperado: `>0`. Se `0`, o ServiceMonitor não deu match — checar
`oc -n openshift-user-workload-monitoring logs prometheus-user-workload-0 | grep banking-api`.

### 3. istio_requests_total tem o label consumer_id?

```bash
curl -sk -H "Authorization: Bearer $(oc whoami -t)" \
  "https://$THANOS/api/v1/query?query=istio_requests_total%7Brequest_headers_x_consumer_id!%3D%22%22%7D" \
  | jq '.data.result | length'
```

Esperado: `>0`. Se `0`, a Telemetry CR não pegou — validar
`spec.targetRefs` apontando pro Gateway correto.

### 4. Plugin renderiza custo em BRL?

Abrir Console → **Custom Connectivity Link → Cost**. Esperado:
- 1 linha por APIKey (alice, bob, carol) + linha `anonymous` se houver
  tráfego IA público
- Badge de tier (gold/silver/bronze) igual ao `plan-id` da APIKey
- Coluna `Cost (24h)` populada em `R$`
- Δ vs 24h anteriores mostrando ↑ ou ↓ (só depois de 24h+ de dados)

Sanity da fórmula (usando os defaults de demo):
```
Se alice (gold) fez 200 calls e 5.000 tokens em 24h:
cost = 200 × 0.05 / 1000 + 5000 × 0.10 / 1000
     = 0.01 + 0.50 = R$ 0.51
```

### 5. Dashboard Grafana bate com o plugin?

Abrir dashboard `RHCL API Costs`. Comparar **Total cost (24h)** contra a
soma da coluna `Cost` do plugin — devem bater com margem <1% (o plugin
faz snapshot; Grafana usa range query com step).

Alterar `price_tokens_per_1k` no topo do dashboard pra `0.40` → total
cost dobra (só no Grafana; plugin não muda porque lê ConfigMap).

### 6. Pricing runtime — trocar preço sem restart

```bash
oc -n custom-rhcl-console edit configmap custom-rhcl-console-config
# Trocar gold.tokens_per_1k de 0.10 pra 1.00 (10x) e salvar.

# Recarregar a página Cost em <60s — coluna Cost do gold multiplica por 10.
```

### 7. Fallback sem pricing configurado

```bash
oc -n custom-rhcl-console patch configmap custom-rhcl-console-config \
  --type=merge -p '{"data":{"costPricing":""}}'
```

Esperado: em <60s a coluna `Cost (24h)` some da UI, mas as colunas de
`Calls` e `Tokens` permanecem — degradação graciosa.

Restaurar:
```bash
oc apply -f manifests/04-plugin-config-pricing.yaml
```

## Limitações conhecidas

- **Só banking-api emite tokens.** pix-api / mock-api não têm contador
  IA — aparecem na tabela só com `Calls`, `Tokens = 0`.
- **Endpoints IA são anônimos por design no PoC.** `AuthPolicy` marca
  `/api/v1/chat/completions`, `/embeddings` e `/responses` como
  `anonymous: {}`, então tokens dessas chamadas caem no bucket
  `anonymous`. Pra atribuir a alice/bob/carol, remover o bloco `ai-mock`
  em `connectivity-authpolicy-apikey.yml.j2` (quebra o cenário do mock IA público).
- **Período fixo em 24h no plugin.** Picker de janela é follow-up. Pra
  outras janelas hoje usa o dashboard Grafana (range arbitrário).
- **Sem multi-currency.** `costCurrency` é rótulo — não converte. Se
  mudar `BRL → USD`, os números continuam iguais, só o `R$` vira `$`.
- **APIKey sem CR aparece como `unknown`** (usuário criou Secret à mão).
  Plugin cai no preço `anonymous` se existir, senão `0`.
- **Tokens são estimativa best-effort do backend** (`prompt_tokens +
  completion_tokens` que o próprio LLM devolve). Se o mock devolver `0`,
  o counter não incrementa — a coluna Tokens fica em 0 sem erro visível.
