REQ 31 — Produto de API via API Administrativa

RHCL PoC · Criar e configurar um produto de API completo via Kubernetes API

O requisito

"Permitir criar e configurar completamente um produto de API através de uma API administrativa."

Em RHCL/Kuadrant, a API administrativa É a API do Kubernetes. Cada peça que compõe um produto é um CRD exposto em /apis/<group>/<version>/.... Qualquer cliente HTTP (curl, Postman, Python, Go) com Bearer token de uma SA com RBAC consegue criar, alterar, listar e remover um produto inteiro — sem console, sem GitOps, sem Ansible.

Esta demo cria o produto pix-api ponta-a-ponta de duas formas: declarativa (oc apply) e REST cru (curl + token de SA, zero oc). Ambas chegam ao mesmo estado e provam o requisito.

Modelo: composição de um produto de API

Todos os CRs abaixo são manipuláveis via REST do K8s API. Esta demo cria todos:

CRGrupo / VersãoPapel
HTTPRoutegateway.networking.k8s.io/v1Roteamento, matches, filtros (URLRewrite, headers)

Demo: criar o produto pix-api

O caminho mais idiomático: oc apply pra cada manifest, mais o smoke test.

cd tests/req031
./scripts/create-via-oc.sh

O script descobre o host do banking-api-connectivity, aplica os 6 manifests, aguarda AuthPolicy.Enforced=True, e faz o smoke test:

TesteEsperado
curl /pix/v1 sem api-key401
curl /pix/v1 com api-key200
Burst 7x (plano bronze = 5/min)5× 200 + 2× 429

O ponto do item 31: nenhuma ferramenta proprietária — só HTTP + Bearer.

cd tests/req031
./scripts/create-via-k8s-api.sh

O script:

  1. Aplica 06-rbac.yaml via oc (único passo cluster-admin — cria a SA req031-product-admin).
  2. Gera token efêmero (1h) da SA via oc create token.
  3. Cria cada CR via curl POST $APISERVER/apis/... autenticado só pelo Bearer.
  4. Lista os APIProducts via curl GET pra confirmar.
  5. Smoke test 401/200.

Exemplo do POST cru pra criar o APIProduct (extraído do script):

APISERVER=$(oc whoami --show-server)
TOKEN=$(oc -n rhcl-apps create token req031-product-admin --duration=1h)
curl -sk -X POST \
  "$APISERVER/apis/devportal.kuadrant.io/v1alpha1/namespaces/rhcl-apps/apiproducts" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/yaml" \
  --data-binary @manifests/01-apiproduct.yaml
Em produção, o token seria de um Workload Identity (SPIFFE/OIDC) ou de um OIDC-federated client, não de uma SA com token de longa duração. A demo usa SA token efêmero (1h) pra simplicidade.

Pra explorar à mão, sem rodar os scripts:

HOST=$(oc -n rhcl-apps get httproute banking-api-connectivity \
       -o jsonpath='{.spec.hostnames[0]}')
KEY=$(oc -n rhcl-apps get secret pix-api-key-tester \
      -o jsonpath='{.data.api_key}' | base64 -d)

# sem auth -> 401
curl -sk -o /dev/null -w "%{http_code}\n" "https://$HOST/pix/v1"

# com auth -> 200
curl -sk -o /dev/null -w "%{http_code}\n" -H "api-key: $KEY" "https://$HOST/pix/v1"

# burst -> 5x 200 + 2x 429 (plano bronze, 5/min)
for i in $(seq 1 7); do
  curl -sk -o /dev/null -w "%{http_code} " -H "api-key: $KEY" "https://$HOST/pix/v1"
done; echo

Listar o produto via REST puro com SA token:

APISERVER=$(oc whoami --show-server)
TOKEN=$(oc -n rhcl-apps create token req031-product-admin --duration=10m)
curl -sk -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/apis/devportal.kuadrant.io/v1alpha1/namespaces/rhcl-apps/apiproducts/pix-api" \
  | python3 -m json.tool | head -30

Caveats / pegadinhas

  • Dev portal habilitado: o APIProduct só reconcilia se Kuadrant.spec.components.developerPortal.enabled=true. Sem isso, o CR fica criado mas sem reconciliação — auth + rate limit funcionam mesmo assim (vêm de AuthPolicy/PlanPolicy direto).
  • 1 AuthPolicy + 1 RateLimitPolicy por HTTPRoute: PlanPolicy substitui RateLimitPolicy (não use ambos no mesmo route).
  • Path-based: este produto reusa o host do banking-api. Pra um produto em host separado, adicionar um listener no Gateway (fora do escopo do item 31).
  • Secret vs APIKey CR: a auth real é via Secret (label-selected pela AuthPolicy). O APIKey CR é objeto de governança (request/approve); ao aprovar, o developer-portal-controller materializa um Secret próprio. Esta demo usa Secret de valor fixo pra reprodutibilidade.
