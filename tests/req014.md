### Req 14 — Allow CORS configuration at the API level.

**Goal:** the gateway should be able to create configurations for CORS at the gateway level.

**Scenario:**

````
SCENARIO 1 — Without Gateway / CORS problem

+-------------------+                         +----------------------+
|                   |                         |                      |
|  Client Browser   |                         |  Backend API         |
|                   |                         |  api.otherdomain.com |
+---------+---------+                         +----------+-----------+
          |                                              ^
          | 1. Loads frontend                            |
          v                                              |
+-------------------+                                    |
|                   |                                    |
|  Frontend Web     |                                    |
|  app.mydomain.com |                                    |
|                   |                                    |
+---------+---------+                                    |
          |                                              |
          | 2. JavaScript calls API                      |
          |    fetch("https://api.otherdomain.com")      |
          +--------------------------------------------->|
                                                         |
                                                         |
          <------------------ BLOCKED -------------------+
                     Browser enforces CORS policy

Problem:
The frontend was loaded from:

  https://app.mydomain.com

But JavaScript tries to call:

  https://api.otherdomain.com

Since these are different origins, the browser requires CORS headers.
If the backend does not allow this origin, the request fails.
````

````
SCENARIO 2 — With RHCL / Gateway API handling CORS

+-------------------+
|                   |
|  Client Browser   |
|                   |
+---------+---------+
          |
          | 1. Loads frontend
          v
+-------------------+
|                   |
|  Frontend Web     |
|  app.mydomain.com |
|                   |
+---------+---------+
          |
          | 2. JavaScript calls Gateway
          |    fetch("https://api.mydomain.com")
          v
+-------------------------------+
|                               |
|  RHCL / Gateway API           |
|  api.mydomain.com             |
|                               |
|  - Terminates TLS             |
|  - Applies CORS policy        |
|  - Handles OPTIONS preflight  |
|  - Proxies to backend         |
|                               |
+---------------+---------------+
                |
                | 3. Proxy to real backend
                v
+-------------------------------+
|                               |
|  Backend API                  |
|  backend.otherdomain.com      |
|                               |
+-------------------------------+

Result:
The browser sees the request as allowed because the Gateway
responds with proper CORS headers, such as:

  Access-Control-Allow-Origin: https://app.mydomain.com
  Access-Control-Allow-Methods: GET, POST, OPTIONS
  Access-Control-Allow-Headers: Authorization, Content-Type
  ````

**Frontend (PoC console):**

Open [tests/req014/index.html](req014/index.html) in a browser served from a
different origin than the backend (see [tests/req014/README.md](req014/README.md)
for how to run it). With the DevTools Console + Network tab open:

1. Pick one of the **Direct →** presets (or paste the backend URL into
   *Backend URL*) and click **Fetch** — observe the CORS error printed by the
   browser in the Console (`No 'Access-Control-Allow-Origin' header is present`).
2. Apply the HTTPRoute below (after filling in the placeholders) and copy the
   resulting hostname into the *RHCL Gateway URL* field, click **Save**, then
   click the **Via RHCL Gateway** preset → **Fetch**. The request should now
   succeed and the headers shown in the on-screen log should include the
   `Access-Control-*` ones.

> ⚠ **OPTIONS preflight caveat.** The filter below adds CORS headers to every
> response, but the browser also requires the preflight `OPTIONS` to return a
> **2xx** status. If your backend returns a non-2xx (e.g. 403) for `OPTIONS`,
> the browser will still block the request even with the headers injected.
> Validate with: `curl -i -X OPTIONS <backend-url> -H 'Origin: http://x' -H 'Access-Control-Request-Method: GET'`

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: req014-cors
  namespace: rhcl-apps
spec:
  parentRefs:
    - name: rhcl-apps-gateway
      namespace: openshift-ingress
  hostnames:
    - <INSIRA O HOSTNAME PUBLICO AQUI>   # ex: req014.apps.cluster1.poc.rhcl.com.br
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /                       # ajuste o prefixo se quiser restringir (ex: /api/v1)
      filters:
        - type: ResponseHeaderModifier
          responseHeaderModifier:
            set:
              - name: Access-Control-Allow-Origin
                value: "*"                 # ou troque por https://<seu-frontend> p/ restringir
              - name: Access-Control-Allow-Methods
                value: "GET,POST,PUT,PATCH,DELETE,OPTIONS"
              - name: Access-Control-Allow-Headers
                value: "accept,authorization,content-type,x-requested-with,x-flow-trace-id,x-client-app"
              - name: Access-Control-Allow-Credentials
                value: "true"
              - name: Access-Control-Max-Age
                value: "86400"
              - name: Vary
                value: Origin
      backendRefs:
        - name: <INSIRA O BACKEND AQUI>    # nome do Service no cluster (ex: banking-api-v1)
          port: <INSIRA A PORTA AQUI>      # ex: 8080
          # se o Service estiver em outro namespace, descomente abaixo
          # e crie um ReferenceGrant correspondente no namespace de destino:
          # namespace: <INSIRA O NAMESPACE DO SERVICE>
---
apiVersion: gateway.networking.k8s.io/v1
kind: ReferenceGrant
metadata:
  name: phpapp
  namespace: phpapp
spec:
  from:
  - group: gateway.networking.k8s.io
    kind: HTTPRoute
    namespace: rhcl-apps
  to:
  - group: ""
    kind: Service          
```


**Expected result:**
The CORS problem should not occur after configuring the access through RHCL
