WebSockets for real-time APIs disconnected

Demonstrates that RHCL routes WebSocket traffic between the frontend and backend, enabling real-time balance and transfer-status updates.

Scenario

[ Frontend / Browser ]                  [ RHCL / Gateway (Istio) ]            [ Backend (Quarkus) ]
        |                                          |                                  |
        |  GET /ws/live HTTP/1.1                   |                                  |
        |  Upgrade: websocket                      |                                  |
        |  Connection: Upgrade                     |                                  |
        | ---------------------------------------->|  HTTPRoute match: /ws             |
        |                                          | -------------------------------->|
        |                                          |  HTTP/1.1 101 Switching Protocols |
        |                                          |<---------------------------------|
        |  101 Switching Protocols                 |                                  |
        |<-----------------------------------------|                                  |
        |                                          |                                  |
        |  ===== WebSocket connection open =====   |                                  |
        |                                          |                                  |
        |          { "type": "backend.health" }    |                                  |
        |<=========================================|<=================================|
        |    { "type": "transfer.pending" }        |                                  |
        |<=========================================|<=================================|
        |    { "type": "transfer.processing" }     |                                  |
        |<=========================================|<=================================|
        |    { "type": "transfer.completed" }      |                                  |
        |<=========================================|<=================================|
        |    { "type": "balance.updated" }         |                                  |
        |<=========================================|<=================================|
HTTPRoute required. The /ws path must be mapped in the gateway HTTPRoute. Without that rule, Istio rejects the connection before the HTTP → WebSocket upgrade happens — resulting in WebSocket connection failed in the browser console.

WebSocket connection

Transfer trigger

Trigger a transfer via REST API to generate WebSocket events. The backend will broadcast transfer.pending → transfer.processing → transfer.completed → balance.updated through the WebSocket connection above.
