RHCL Lab
REQ 051 + 056

Gateway mTLS enforcement

Demonstrate that the RHCL Gateway requires mutual TLS, validating client certificates against a single CA (REQ 056) and through a certificate chain (REQ 051).

Scenario

                       ┌──────────────────────────────────────────────────────┐
                       │         Gateway: req051-mtls-gateway                 │
                       │         (gatewayClassName: istio)                    │
                       │                                                      │
[ client ]             │  Listener: https-single-ca (REQ 056)                │
    │                  │    hostname: req056-mtls.                    │
    │  TLS handshake   │    EnvoyFilter: require_client_certificate=true      │
    │  + client cert   │      trusted_ca: intermediate-ca                    │
    ├────────────────► │                                                      │  ──► banking-api-v1
    │                  │  Listener: https-chain-ca (REQ 051)                 │       (rhcl-apps)
    │                  │    hostname: req051-mtls.                    │
    │                  │    EnvoyFilter: require_client_certificate=true      │
    │                  │      trusted_ca: root-ca                            │
    │                  │                                                      │
                       └──────────────────────────────────────────────────────┘
                                         │
                                         ▼
                              x-forwarded-client-cert (XFCC)
                              injected by Istio into backend request
Browser limitation. Browsers cannot present arbitrary client certificates from JavaScript. This page provides curl commands to execute from a terminal. The browser-based fetch below will fail (as expected) unless you import the client cert into your OS certificate store.
