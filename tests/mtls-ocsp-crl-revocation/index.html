REQ 050

OCSP stapling + CRL validation

On top of the mTLS Gateway (see REQ 051), demonstrate certificate revocation: a CRL rejects a revoked client cert, and OCSP stapling attaches the server cert's OCSP status to the TLS handshake. Both are applied via EnvoyFilter on the Envoy DownstreamTlsContext — the only path exposing crl and ocsp_staple.

Scenario

                       ┌──────────────────────────────────────────────────────┐
                       │      Gateway: req050-revocation-gateway              │
                       │      (gatewayClassName: openshift-default / Istio)   │
                       │                                                      │
[ client ]             │  Listener: https-crl                                │
    │                  │    hostname: req050-crl.                     │
    │  TLS handshake   │    EnvoyFilter: require_client_certificate=true      │
    │  + client cert   │      validation_context.trusted_ca: intermediate-ca  │
    ├────────────────► │      validation_context.crl: crl.pem  ◄─ revocation  │  ──► banking-api-v1
    │                  │                                                      │       (rhcl-apps)
    │  status_request  │  Listener: https-ocsp                               │
    ├────────────────► │    hostname: req050-ocsp.                    │
    │  ◄── staple ──── │    EnvoyFilter: require_client_certificate=true      │
    │                  │      staple via SDS secret: tls.ocsp-staple         │
                       └──────────────────────────────────────────────────────┘
Browser limitation. Browsers cannot present arbitrary client certificates from JavaScript, and OCSP staples are only visible at the TLS layer. This page generates the curl and openssl commands to run from a terminal. The browser fetch below will fail (as expected) without a client cert.
