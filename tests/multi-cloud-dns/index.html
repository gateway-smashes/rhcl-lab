Req 09 — DNS Management

DNS Management across Multi-Cloud

Validate DNSPolicy integration with AWS Route53, Azure DNS, GCP Cloud DNS, and on-premise CoreDNS.

Scenario

Goal: Expose a single API hostname across multiple environments (AWS, Azure, GCP, on-premise) with DNS-based load balancing and failover.

This test validates that:

  • DNSPolicy is correctly configured for each provider (Route53, Azure DNS, Cloud DNS, CoreDNS)
  • DNS records are created and updated by the Kuadrant controller
  • Load balancing weights are respected across clusters
  • DNS resolution returns expected IPs and respects TTL

  loadBalancing:
    defaultGeo: true
    weight: 80

Load Balancing

Weight Distribution

When multiple clusters expose the same hostname with different weights, DNS queries are distributed proportionally.

Cluster / Region Weight Expected Traffic %
Cluster A (Primary) 80 80%
Cluster B (Secondary) 20 20%
Note: DNS results are cached globally (TTL typically 60–300s). To observe actual distribution, query multiple times with different resolvers or wait for TTL expiration.

AWS Route53 integration — dnspolicy-aws-route53.yaml Open file 
# DNSPolicy for AWS Route53
#
# Prerequisites:
# 1. Hosted zone created in Route53 (e.g., apps.example.com)
# 2. IAM user or role with route53:* permissions on that zone
# 3. Access key ID and secret key from AWS IAM
#
# Installation:
#   oc apply -f dnspolicy-aws-route53.yaml
#
# After applying:
#   oc describe dnspolicy rhcl-apps-gateway-dns -n openshift-ingress

---
apiVersion: v1
kind: Secret
metadata:
  name: rhcl-dns-credentials
  namespace: openshift-ingress
type: Opaque
stringData:
  # AWS credentials for Route53 access
  AWS_ACCESS_KEY_ID: "AKIA..."  # Replace with your access key
  AWS_SECRET_ACCESS_KEY: "..."  # Replace with your secret key
  AWS_REGION: "us-east-2"       # Adjust to your region

---
apiVersion: kuadrant.io/v1
kind: DNSPolicy
metadata:
  name: rhcl-apps-gateway-dns
  namespace: openshift-ingress
  labels:
    app: rhcl
spec:
  # Target the main RHCL Gateway
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: rhcl-apps-gateway

  # Reference the AWS credentials secret
  providerRefs:
    - name: rhcl-dns-credentials

  # Load balancing configuration (optional)
  # Comment out to disable load balancing
  loadBalancing:
    # defaultGeo: true means this cluster is the fallback for unmapped regions
    defaultGeo: true
    # weight: 80 means this cluster receives 80% of DNS queries globally
    # Pair with weight: 20 on another cluster for 80/20 split
    weight: 80

# DNSPolicy for Google Cloud DNS
#
# Prerequisites:
# 1. Google Cloud DNS zone created (e.g., apps-zone)
# 2. Service account with dns.admin role
# 3. Service account key file (JSON)
#
# Create service account:
#   gcloud iam service-accounts create kuadrant-dns
#   gcloud projects add-iam-policy-binding PROJECT_ID \
#     --member="serviceAccount:kuadrant-dns@PROJECT_ID.iam.gserviceaccount.com" \
#     --role="roles/dns.admin"
#   gcloud iam service-accounts keys create sa-key.json \
#     --iam-account=kuadrant-dns@PROJECT_ID.iam.gserviceaccount.com
#
# Installation:
#   oc create secret generic rhcl-dns-credentials \
#     --from-file=GOOGLE_APPLICATION_CREDENTIALS=sa-key.json \
#     -n openshift-ingress
#   oc apply -f dnspolicy-gcp-cloud-dns.yaml
#
# After applying:
#   oc describe dnspolicy rhcl-apps-gateway-dns -n openshift-ingress

---
apiVersion: v1
kind: Secret
metadata:
  name: rhcl-dns-credentials
  namespace: openshift-ingress
type: Opaque
stringData:
  # GCP service account credentials (full JSON)
  GOOGLE_APPLICATION_CREDENTIALS: |
    {
      "type": "service_account",
      "project_id": "your-project-id",
      "private_key_id": "...",
      "private_key": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n",
      "client_email": "kuadrant-dns@your-project-id.iam.gserviceaccount.com",
      "client_id": "...",
      "auth_uri": "https://accounts.google.com/o/oauth2/auth",
      "token_uri": "https://oauth2.googleapis.com/token",
      "auth_provider_x509_cert_url": "https://www.googleapis.com/oauth2/v1/certs",
      "client_x509_cert_url": "..."

  GOOGLE_PROJECT_ID: "your-project-id"

On-premise CoreDNS integration — dnspolicy-onprem-coredns.yaml Open file 
# DNSPolicy for On-Premise CoreDNS
#
# Prerequisites:
# 1. CoreDNS deployed in OpenShift or Kubernetes cluster
# 2. CoreDNS configured to serve the zone (e.g., apps.local)
# 3. Kuadrant DNS controller has access to CoreDNS namespace
#
# CoreDNS is typically deployed in:
#   - kube-system namespace (native Kubernetes)
#   - openshift-dns namespace (OpenShift)
#
# Installation:
#   oc apply -f dnspolicy-onprem-coredns.yaml
#
# After applying:
#   oc describe dnspolicy rhcl-apps-gateway-dns -n openshift-ingress
#   oc logs -n kuadrant-system -l app=kuadrant-operator | grep dns

---
apiVersion: v1
kind: Secret
metadata:
  name: rhcl-dns-credentials
  namespace: openshift-ingress
type: Opaque
stringData:
  # CoreDNS requires in-cluster kubeconfig access
  # No external credentials needed - the operator uses its service account
  # to communicate with CoreDNS API
  COREDNS_ZONE: "apps.local"
  COREDNS_NAMESPACE: "openshift-dns"

---
apiVersion: kuadrant.io/v1
kind: DNSPolicy
metadata:
  name: rhcl-apps-gateway-dns
  namespace: openshift-ingress
  labels:
    app: rhcl
spec:
  # Target the main RHCL Gateway
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: rhcl-apps-gateway

  # Reference the CoreDNS configuration
  providerRefs:
    - name: rhcl-dns-credentials

  # Load balancing configuration
  # CoreDNS on-premise typically uses weight-based distribution
  loadBalancing:
    # This cluster's share of traffic
    weight: 100  # Single cluster: 100
    # For multiple on-premise clusters:
    # Cluster A: weight: 70
    # Cluster B: weight: 30
    defaultGeo: true
Standalone internal CoreDNS demo — coredns-internal-zone-demo.yaml Open file 
# Standalone CoreDNS - Internal Zone Demo (on-premise, no MetalLB)
#
# Purpose:
#   Demonstrate creating a DNS zone in CoreDNS and resolving records from
#   INSIDE the cluster, without any external LoadBalancer. The CoreDNS
#   instance is exposed only via a ClusterIP Service, so resolution works
#   for in-cluster clients (pods) only. Exposing the zone outside the
#   cluster would require MetalLB (bare metal) or a cloud LoadBalancer -
#   out of scope for this internal demo.
#
# This is self-contained and independent from the Ansible-driven
# `kuadrant-coredns` flow (automation/roles/coredns_dns). It is meant for a
# quick, reproducible "create a zone and query it" demonstration.
#
# Apply:
#   oc apply -f coredns-internal-zone-demo.yaml
#
# Query (from inside the cluster):
#   COREDNS_IP=$(oc get svc coredns-poc -n req009-coredns -o jsonpath='{.spec.clusterIP}')
#   oc run dnsutils --rm -it --restart=Never -n req009-coredns \
#     --image=registry.k8s.io/e2e-test-images/jessie-dnsutils:1.3 -- \
#     dig @${COREDNS_IP} banking-api.poc.internal +short

---
apiVersion: v1
kind: Namespace
metadata:
  name: req009-coredns
  labels:
    app.kubernetes.io/part-of: rhcl-req009

---
apiVersion: v1
kind: ConfigMap
metadata:
  name: coredns-poc
  namespace: req009-coredns
data:
  # CoreDNS configuration. Listens on 5353 (unprivileged port, so the pod
  # runs under the OpenShift restricted-v2 SCC without extra capabilities).
  # The Service below maps port 53 -> targetPort 5353.
  Corefile: |
    poc.internal:5353 {
        file /etc/coredns/db.poc.internal
        log
        errors
    }
    .:5353 {
        forward . /etc/resolv.conf
        cache 30
        errors
    }
    health :8080
    ready :8181

  # The actual zone file for poc.internal. Add or edit A records here, then
  # bump the SOA serial and roll the Deployment to publish the change.
  db.poc.internal: |
    $ORIGIN poc.internal.
    $TTL 60
    @   IN  SOA ns1.poc.internal. admin.poc.internal. (
            2026061001 ; serial (YYYYMMDDnn - bump on every change)
            7200       ; refresh
            3600       ; retry
            1209600    ; expire
            60 )       ; minimum TTL
    @            IN  NS   ns1.poc.internal.
    ns1          IN  A    10.96.0.10
    ; Example API records - point these at real Service ClusterIPs if you
    ; want the names to resolve to live backends inside the cluster.
    banking-api  IN  A    10.96.0.20
    api          IN  A    10.96.0.30

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: coredns-poc
  namespace: req009-coredns
  labels:
    app: coredns-poc
spec:
  replicas: 1
  selector:
    matchLabels:
      app: coredns-poc
  template:
    metadata:
      labels:
        app: coredns-poc
    spec:
      containers:
        - name: coredns
          # Public CoreDNS image. In a restricted/air-gapped client cluster,
          # mirror this to the internal registry (or reuse the CoreDNS image
          # already pulled for the kuadrant-coredns instance) and override here.
          image: registry.k8s.io/coredns/coredns:v1.11.3
          args: ["-conf", "/etc/coredns/Corefile"]
          ports:
            - name: dns-udp
              containerPort: 5353
              protocol: UDP
            - name: dns-tcp
              containerPort: 5353
              protocol: TCP
            - name: health
              containerPort: 8080
              protocol: TCP
            - name: ready
              containerPort: 8181
              protocol: TCP
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10
          readinessProbe:
            httpGet:
              path: /ready
              port: 8181
            initialDelaySeconds: 5
            periodSeconds: 5
          volumeMounts:
            - name: config
              mountPath: /etc/coredns
              readOnly: true
          resources:
            requests:
              cpu: 50m
              memory: 64Mi
            limits:
              cpu: 200m
              memory: 128Mi
          securityContext:
            allowPrivilegeEscalation: false
            runAsNonRoot: true
            capabilities:
              drop: ["ALL"]
            seccompProfile:
              type: RuntimeDefault
      volumes:
        - name: config
          configMap:
            name: coredns-poc
            items:
              - key: Corefile
                path: Corefile
              - key: db.poc.internal
                path: db.poc.internal

---
apiVersion: v1
kind: Service
metadata:
  name: coredns-poc
  namespace: req009-coredns
  labels:
    app: coredns-poc
spec:
  type: ClusterIP
  selector:
    app: coredns-poc
  ports:
    - name: dns-udp
      port: 53
      targetPort: 5353
      protocol: UDP
    - name: dns-tcp
      port: 53
      targetPort: 5353
      protocol: TCP
