# REQ 03 — Native Horizontal Pod Autoscaler (HPA)

The solution must ship with a **native** horizontal scaling component for
its workloads. On OpenShift / Kubernetes, the native primitive is the
`HorizontalPodAutoscaler` from `autoscaling/v2`. There is no need for an
external operator (KEDA, Knative serving, etc.) to satisfy this
requirement.

The PoC targets the **Gateway API data plane** — the workload that
actually terminates client traffic for RHCL. In this lab the connectivity
`Gateway rhcl-apps-gateway` is reconciled by the OpenShift
ingress-managed Istio controller, which provisions
`Deployment/rhcl-apps-gateway-istio` in `openshift-ingress`. Scaling that
deployment is what protects every application published through the
gateway. The same HPA pattern applies to any other `Gateway` that the
solution exposes — only `scaleTargetRef.name` and `namespace` change.

For the interactive demo, the manifests, and the end-to-end validation
walkthrough, see [req003/](req003/README.md).
